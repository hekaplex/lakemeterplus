# Merge Plan — Combining `lakemeter-oss` and `databricks-cost-observability` into `satsyil_lakemeterplus`

## Strategy

Use **`lakemeter-oss`'s backend/frontend as the host application** (more modern stack: React/TS SPA, SQLAlchemy ORM, structured routers/services/models, real test suite, active Databricks Labs project) and **graft `databricks-cost-observability`'s domain logic in as a new "Observability" module** — new routers under `/api/v1/observability/*`, a ported `core/sql_executor.py` (Statement Execution API client) and `services/*` files kept largely intact, and new frontend pages/nav entries. This avoids a risky rewrite of either app's data-access layer (Postgres/SQLAlchemy vs. UC Statement-Execution-API are not worth unifying) while giving users one deployed app with both estimation and observability.

Legend: **P0** = required before anything else works, **P1** = required for a usable merged v1, **P2** = polish/parity, **P3** = nice-to-have/future. **Status** reflects what's actually landed in `satsyil_lakemeterplus/src` — see `TODO.md` for the fuller narrative and verification notes.
